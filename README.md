# Масиви — демонстрації

Демонстраційні програми до заняття 10 курсу «Системне програмування»
(ВСП «Фаховий коледж інформаційних систем і технологій КНЕУ ім. Вадима Гетьмана»).

Тема заняття — **у процесора немає масиву, є лише адреса початку і зсув**: оголошення й ініціалізація, масив у пам'яті й у вікні Disassembly, масив як параметр функції, векторизація, обробка й сортування одновимірного масиву, двовимірний масив у пам'яті, масив і стек, типові помилки.

## Склад рішення

Рішення `Demo_Lecture_10.slnx`: шість проєктів на C і тека зі сценаріями командного рядка.

| Проєкт | Файл | Розділ конспекту | Що показує |

| `Demo4_ops` | `ops.c` | 4.1–4.5 | заповнення `rand`, сума і середнє, min/max з індексом, лінійний пошук, обмін, розворот, вставка, видалення |

## Як відкрити у Visual Studio

**Що має бути встановлено.** Visual Studio (Community достатньо) з компонентом **«Розробка класичних застосунків на C++»** (Desktop development with C++).

**Крок 1. Відкрити рішення.** Двічі клацнути `Demo_Lecture_10.slnx` або *File → Open → Project/Solution*. У Solution Explorer з'являться шість проєктів і тека **Сценарії**.

> Файл рішення збережено в новому форматі `.slnx`. Якщо ваша версія Visual Studio його не відкриває, оновіть її або відкрийте потрібний `.vcxproj` напряму.

**Крок 2. Зібрати обидві конфігурації.** На панелі зверху вибрати **Debug** і **x64**, *Build → Build Solution* (Ctrl+Shift+B). Потім перемкнути на **Release** і зібрати ще раз.

**Крок 3. Запускати.** `Ctrl+F5` — без налагоджувача, `F5` — під налагоджувачем. F5 запускає **стартовий проєкт** (у Solution Explorer він жирний). Зручніше один раз налаштувати: правою кнопкою на рішенні → *Properties* → *Startup Project* → **Current selection**. Тоді F5 запускає проєкт, виділений у Solution Explorer.

## Що робити в налагоджувачі

| Клавіша | Дія |
|---|---|
| `F9` | поставити або зняти точку зупину на рядку |
| `F5` | запустити під налагоджувачем / продовжити до наступної точки зупину |
| `Ctrl+F5` | запустити **без** налагоджувача |
| `F10` | виконати рядок (у вікні Disassembly — одну команду) |
| `F11` | зайти всередину функції |
| `Shift+F5` | зупинити налагодження |
| `Ctrl+Alt+D` | вікно **Disassembly** (під час налагодження) |
| `Ctrl+Alt+M`, `1` | вікно **Memory 1** (під час налагодження) |

**`Demo3_memory` — розділ 3 повністю.**

1. **Debug, пам'ять.** F9 на рядку 18 (`for` після оголошень), F5. *Debug → Windows → Memory → Memory 1*, у полі *Address* — `a`: п'ять чисел по чотири байти, `0a 00 00 00 14 00 00 00 …`. Те саме для `d` і `c`.
2. **Debug, Disassembly.** *Ctrl+Alt+D*. Під рядком 19 — `mov eax, DWORD PTR a$[rsp+rax*4]`; під рядком 23 — `*8` для `d` і без масштабу для `c`.
3. **Debug, функція.** F9 на рядку 8 (`s += a[i];`), F5. У вікні **Locals** `a` — лише адреса. У вікні **Watch** введіть `a,5` — видно весь масив. У Disassembly під рядком 8 спершу `mov rcx, QWORD PTR a$[rsp]` (адреса), потім `[rcx+rax*4]`.
4. **Release.** Перемкнути конфігурацію на **Release**, F9 на рядку 26, F5, *Ctrl+Alt+D*. Нижче — п'ять команд `add edx, DWORD PTR a$[rsp+…]` (виклик `sum(a, 5)` розгорнуто повністю), далі цикл з `movdqu` і `paddd` — векторизований `sum(big, 1000)`.

Код у Release не повторює вихідний рядок за рядком: налагоджувач «перестрибує» рядки, змінні показуються як *optimized away*. Так і має бути.

**`Demo6_matrix` (Debug).** F9 на рядку 23 (`printf(" %4d", m[i][j]);`), F5, *Ctrl+Alt+D*: `imul rax, rax, 16` — початок рядка, `[rax+rcx*4]` — елемент. Вікно Memory з адресою `m` — 12 чисел підряд: `0b`, `0c`, `0d`, `0e`, `15`, …

**`Demo7_pitfalls`.** Аргументи `stack` і `overrun` задаються сценарієм або в *Properties → Configuration Properties → Debugging → Command Arguments*. Під налагоджувачем (F5) аргумент `stack` зупиняється на винятку *Stack overflow* у `__chkstk`; вікно **Call Stack** показує `big_local`.

## Налаштування проєктів

Проєкти створено зі стандартного шаблону консольної програми з тими самими змінами, що й у демонстраціях до занять 8–9. **Не повертайте їх**, інакше вікно Disassembly не збігатиметься з тим, що показано на занятті:

| Параметр (*Properties → C/C++*) | Значення | Навіщо |
|---|---|---|
| *General → Warning Level* | `/W4` | попередження рівня 4; помилки з `Demo7_pitfalls` компілюються **без** попереджень — це частина демонстрації |
| *General → Support Just My Code Debugging* | No (Debug) | без цього на початку кожної функції з'являється зайвий виклик |
| *Code Generation → Basic Runtime Checks* | Default (Debug) | без цього в машинному коді з'являються додаткові перевірки стека. **Виняток — `Demo7_pitfalls`**: там у Debug стоїть `/RTC1` (*Both*), щоб показати повідомлення *Stack around the variable was corrupted* |
| *General → Debug Information Format* | `/Zi` (Debug) | звичайний `.pdb` замість режиму Edit and Continue |
| *Output Files → Assembler Output* | `/FA` | лістинг асемблера `*.asm` у теці `x64\Debug` / `x64\Release` проєкту — для самостійного порівняння |
| *Optimization → Whole Program Optimization* | No (Release) | інакше компілятор не створює лістинг: код генерується лише під час компонування |
| *Command Line → Additional Options* | `/utf-8` | вихідні файли збережено в UTF-8 |

## Як зібрати з командного рядка

**Developer Command Prompt for VS**, з кореня репозиторію:

```
msbuild Demo_Lecture_10.slnx /p:Configuration=Debug /p:Platform=x64
msbuild Demo_Lecture_10.slnx /p:Configuration=Release /p:Platform=x64
```

Окремий файл:

```
cl /nologo /Od Demo3_memory\memory.c          -> memory.exe, без оптимізації
cl /nologo /O2 Demo3_memory\memory.c          -> memory.exe, з оптимізацією
cl /nologo /O2 /FA /c Demo3_memory\memory.c   -> memory.asm, лістинг асемблера
```

## Відомі граблі

**Адреси не збігаються з конспектом.** Так і має бути: стек розміщується за іншою адресою на кожному запуску. Збігаються відстані між адресами: 4 для `int`, 8 для `double`, 1 для `char`.

**Рядок `u` у `Demo2_decl` щоразу інший.** Неініціалізований локальний масив містить те, що залишилось у стеку. Саме це й показується.

**`Demo7_pitfalls stack` нічого не друкує про `local`, а код завершення `-1073741571`.** Так і має бути: це `0xC00000FD`, переповнення стека. Процес завершено до першого рядка `big_local`.

**`Demo7_pitfalls overrun` у Debug відкриває вікно *Debug Error!*.** Це перевірка `/RTC`, вона й демонструється. Натисніть **Abort** (завершити) або **Ignore** (продовжити). У Release вікна немає — помилка не видна, але вона є.

**`Demo7_pitfalls` у Release друкує `limit = 100` двічі.** Так і має бути: оптимізатор прочитав `limit` до циклу. Запис за межу масиву `data` все одно відбувся — розбір у розділі 7 конспекту.

**Консоль закривається одразу після F5.** Поставте точку зупину на `return 0` або вимкніть *Tools → Options → Debugging → General → Automatically close the console when debugging stops*.

**Кодування сценаріїв.** Файли `.cmd` збережено в **UTF-8 з CRLF**, перший рядок після `@echo off` — `chcp 65001 > nul`.
